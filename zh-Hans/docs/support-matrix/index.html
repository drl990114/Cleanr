发布准备

本页记录验证情况和发布门槛，不代表所有支持目标都已经在用户机器上验收。 最近审阅日期：2026-09-04。

版本范围与发布核验​

分类筛选、跨筛选累积选择与 Shift+A 全局选择适用于 0.15.0 及后续版本。 下方兼容性说明记录 0.15.0 的恢复记录变更，详情见 更新记录。

公开发布状态及各平台的 release-evidence.json 请查看 v0.15.0 发行页。 下方记录历史源码检查与仍需进行的系统回收站验收，不能替代 0.15.0 发行包的安装验证。 录屏演示继续标注其实际版本 v0.14.0。 较新提交通过检查，不会使旧发行包自动获得相同验证。

升级与兼容性​

按安装指南保持安装方式一致。可能需要恢复时，升级前保留本地配置与 历史。不要假定旧二进制能读取新版本的计划或清单；也不要手工修改计划来绕过兼容错误， 应使用准备执行的版本重新生成并审阅计划。

0.15.0 兼容性变更： 新恢复记录使用 cleanr.restore.v2，0.15.0 读取器继续接受 v1 历史。not-attempted 表示尚未调用后端，pending 表示已保存操作意图但结果尚未落盘。 中断后，pending 条目需要人工检查原路径、回收站和清单再决定后续操作。不要通过回退 旧二进制处理 v2 记录；请保留状态目录，使用当前或更新的兼容版本。

从 0.15.0 起，清理与恢复在整个操作期间持有状态目录中的操作系统文件锁。另一操作会报告冲突， 进程退出后由操作系统释放锁；不要删除锁文件来绕过。回收站与 JSON 写入仍无法成为 同一个原子事务。文件操作结果落盘失败时，后续条目停止，返回的运行/清单信息供人工 恢复参考。

回退二进制不会撤销文件移动、恢复历史或配置变更。不再需要恢复之前，请保留系统回收站和清单。

正式发布前​

按照仓库的发布流程， 为各项门槛记录确切提交、包版本、平台和验证证据：

  • 发布提交的必要源码检查与发行包冒烟检查全部通过。
  • 每条准备推广的安装路径能够运行 --version、--help 和隔离只读分析。升级与卸载 单独测试，并保留恢复记录。
  • 目标平台通过真实回收站与恢复场景，使用生成样本，并包括原路径冲突与恢复中断。
  • 已部署 /Cleanr/ 网站、CSS/JS、中英文安装页和分享卡都能访问；本地修复不代表部署完成。
  • 发行说明区分已发布能力、待发布能力、格式变更和已知限制。明确授权发布后，再验证 GitHub、npm、crates.io 的公开版本。

真实回收站测试会修改系统回收站，需要单独确定执行范围；只读分析或模拟后端测试 不构成这类操作的授权。

推广前​

围绕开发者缓存展示一个旧项目、每项候选原因、用户选择，以及可恢复的回收站操作。 使用简短的真实操作演示，路径采用生成样本或脱敏内容，把审阅和恢复作为独立步骤。 注明应用版本与平台，仓库独有画面标为未发布。

准确展示候选字节数和已移动字节数，不将它们等同于新增可用空间，也不保证恢复必然 成功。同时展示 TUI 与 Agent 入口，并让用户能看到云端 Agent 的数据边界。

先向小范围开发者试用者收集自愿反馈：安装是否成功、多久理解第一次审阅、空结果 是否造成困惑、是否出现意外规则匹配、恢复是否失败。本页尚未测量基线与真实需求； 本机场景通过不能代替真实用户证据。使用 支持渠道与 私密安全报告，不要索要原始分析 JSON。 对外发布宣传或联系用户是另一个发布决定。
